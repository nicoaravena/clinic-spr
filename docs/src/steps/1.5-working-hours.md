# 1.5 Working hours

## Goal

Know when a practitioner works, so a booking outside their hours can be
refused.

Roadmap row: *`WorkingHours` as dated UTC shifts (slot fits within a
practitioner's hours)*. Concepts: `Vec`, slices, iterators, closures.

## What changed

- `src/working_hours.rs`: `WorkingHours` and `WorkingHoursError`.
  See [working_hours](../reference/working_hours.md).
- `tests/working_hours.rs`.

## Rust concepts

### `Vec` and taking ownership

```rust,ignore
pub fn new(mut shifts: Vec<TimeSlot>) -> Result<Self, WorkingHoursError> {
    shifts.sort_by_key(|shift| shift.start());
    // ...
    Ok(Self { shifts })
}
```

`new` takes the `Vec` by value, so it owns it. It can sort it in place
(`mut` on the parameter allows that) and keep it, with no copy. The caller
gives the vector up.

Book: [Storing Lists of Values with Vectors](https://doc.rust-lang.org/book/ch08-01-vectors.html).

### Closures

`|shift| shift.start()` is a closure, an unnamed function written inline.
`sort_by_key` calls it on each element to get the value to sort by.

Book: [Closures](https://doc.rust-lang.org/book/ch13-01-closures.html).

### Iterators and slice windows

```rust,ignore
if shifts
    .windows(2)
    .any(|pair| pair[1].start() <= pair[0].end())
{
    return Err(WorkingHoursError::ShiftsNotSeparated);
}
```

`windows(2)` yields each pair of neighbors: `[a, b]`, `[b, c]`, and so on.
Once the shifts are sorted, checking neighbors is enough to find any overlap.
`any` stops at the first `true`. Iterators are lazy, so nothing runs until
`any` asks for items.

Book: [Processing a Series of Items with Iterators](https://doc.rust-lang.org/book/ch13-02-iterators.html).

### Returning a slice

```rust,ignore
pub fn shifts(&self) -> &[TimeSlot] {
    &self.shifts
}
```

`&[TimeSlot]` is a borrowed view of the elements. Callers can read and
iterate, but they can't push or reorder, and they don't learn that a `Vec`
sits behind it. `&Vec<T>` turns into `&[T]` automatically.

Book: [The Slice Type](https://doc.rust-lang.org/book/ch04-03-slices.html).

## Design choices worth questioning

- **Dated shifts, not a weekly template.** "Mondays 09-17 in
  Europe/Madrid" depends on the time zone and on daylight saving changes.
  The domain only stores concrete UTC shifts. Expanding a template into
  shifts happens outside the domain, in M2.
- **Touching shifts are rejected.** A slot must fit inside a single shift.
  If 09-12 and 12-17 were allowed, an 11:30-12:30 slot would be refused
  although the practitioner works the whole time. Requiring a gap forces
  those to be written as 09-17.
- **The constructor sorts.** Callers can pass shifts in any order, and
  `shifts()` always returns them sorted.
- **Empty hours are valid.** They accept no slot, which is correct for
  someone with no shifts that period.
- **`contains` is a linear scan.** Shifts are sorted, so a binary search
  would work, but a practitioner has few shifts, and the simple version is
  easier to read.

## Tests

A slot fits inside either shift and when it ends exactly at a shift's end.
It doesn't fit when it runs past the end, falls in the lunch gap, spans two
shifts, or is on a day with no shift. Empty hours accept nothing.
Overlapping, touching and out-of-order overlapping shifts are rejected,
shifts come back sorted, and the error has a message and implements `Error`.
