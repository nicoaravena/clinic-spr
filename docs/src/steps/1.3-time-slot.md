# 1.3 TimeSlot

## Goal

Model a span of time that can't be backwards, and answer the two questions
scheduling depends on: do two spans overlap, and does one contain another?

Roadmap row: *`TimeSlot` (start before end, `overlaps`)*. Concepts:
borrowing, `&self`, operators, chrono.

## What changed

- `src/time_slot.rs`: `TimeSlot` and `TimeSlotError`.
  See [time_slot](../reference/time_slot.md).
- `crates/domain/Cargo.toml`: the `chrono` dependency.
- `tests/time_slot.rs`.

## Rust concepts

### External crates and features

```toml
chrono = { version = "0.4", default-features = false, features = ["std"] }
```

`default-features = false` turns off chrono's optional parts. One of those
is the `clock` feature, which provides `Utc::now()`. Without it the domain
can't read the current time, so "now" must be passed in by the caller. That
keeps every rule deterministic and easy to test.

Book: [Using External Packages](https://doc.rust-lang.org/book/ch07-04-bringing-paths-into-scope-with-the-use-keyword.html#using-external-packages).

### Types that carry rules: `DateTime<Utc>`

`DateTime<Utc>` is a generic type whose parameter is the time zone. A
function that takes `DateTime<Utc>` can't be given a local time by mistake,
so the roadmap's "UTC only" rule is checked by the compiler.

### Methods, `&self` and borrowing

```rust,ignore
pub fn overlaps(&self, other: &TimeSlot) -> bool {
    self.start < other.end && other.start < self.end
}
```

`&self` and `&TimeSlot` are references. The method borrows both slots to
read them, and the caller keeps ownership.

Book: [Method Syntax](https://doc.rust-lang.org/book/ch05-03-method-syntax.html)
and [References and Borrowing](https://doc.rust-lang.org/book/ch04-02-references-and-borrowing.html).

### Comparison operators come from traits

`<` and `<=` work on `DateTime` because chrono implements `PartialOrd` for
it. Operators in Rust are calls to trait methods.

Book: [Operator Overloading](https://doc.rust-lang.org/book/ch20-02-advanced-traits.html#default-generic-type-parameters-and-operator-overloading).

### Getters that return copies

`start()` and `end()` return `DateTime<Utc>` by value. That is cheap because
`DateTime<Utc>` is `Copy`, and so is `TimeSlot`.

## Design choices worth questioning

- **Half-open slots: the start is included, the end is not.** A 09:00-09:30
  appointment and a 09:30-10:00 one don't overlap, which is what a
  receptionist expects. With this rule, the overlap test is two comparisons.
- **A zero-length slot is rejected.** `start >= end` is an error, so every
  slot has some duration.
- **`overlaps` takes `&TimeSlot` although `TimeSlot` is `Copy`.** Passing by
  value would also work. The reference reads as "look, don't take" and stays
  correct if the type stops being `Copy`.
- **`contains` was added alongside `overlaps`.** It wasn't in the roadmap
  row, but step 1.5 needs it to check a slot against a shift.

## Tests

Construction (equal or reversed ends rejected), overlap (partial, nested,
identical, back-to-back, separated), containment (inside, identical, sharing
the start, sharing the end, sticking out on either side, larger than the
container) and the error's message and `Error` impl. Small helpers `at`,
`slot`, `assert_overlap` and `assert_no_overlap` keep each test to a line or
two, and the overlap helpers check both directions.
