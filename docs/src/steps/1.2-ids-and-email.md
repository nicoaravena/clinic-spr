# 1.2 Typed IDs and Email

## Goal

Introduce the first value objects: identifiers that can't be mixed up, and
an email address that is always valid once created.

Roadmap row: *`ClinicId`, `PractitionerId`, `Email` with validation*.
Concepts: structs, newtypes, privacy, `Result`, derive.

## What changed

- `src/ids.rs`: `ClinicId` and `PractitionerId`.
  See [ids](../reference/ids.md).
- `src/email.rs`: `Email` and `EmailError`.
  See [email](../reference/email.md).
- `tests/ids.rs` and `tests/email.rs`: the first integration tests.

## Rust concepts

### Tuple structs and the newtype pattern

A tuple struct has fields without names. With one field it wraps another
type, which is called a newtype:

```rust,ignore
pub struct ClinicId(u64);
pub struct PractitionerId(u64);
```

Both hold a `u64`, but they are different types. A function that takes a
`ClinicId` won't compile if it is passed a `PractitionerId`. The module docs
in `ids.rs` prove this with a `compile_fail` doctest, which passes only if
the code fails to compile.

Book: [Tuple Structs](https://doc.rust-lang.org/book/ch05-01-defining-structs.html#using-tuple-structs-without-named-fields-to-create-different-types)
and [the newtype pattern](https://doc.rust-lang.org/book/ch20-02-advanced-traits.html).

### Privacy and smart constructors

Items are private unless marked `pub`. `Email(String)` is a public struct
with a private field, so code outside the module can't write
`Email("x".to_string())`. The only way in is `Email::parse`, which checks
the input. If you hold an `Email`, it is valid. This is called a smart
constructor, and it makes invalid emails impossible to represent.

Book: [Making Structs and Enums Public](https://doc.rust-lang.org/book/ch07-03-paths-for-referring-to-an-item-in-the-module-tree.html#making-structs-and-enums-public).

### `Result` and early return

`parse` returns `Result<Self, EmailError>`: `Ok` with the value, or `Err`
with the reason. Each check returns early:

```rust,ignore
if address.is_empty() {
    return Err(EmailError::Empty);
}
```

Book: [Recoverable Errors with Result](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html).

### Error enums and the `Error` trait

The error is an enum, not a `String`, so callers can `match` on the reason.
It also implements `Display` (a readable message) and `std::error::Error`,
so it works with `?` and with error-handling libraries later.

Book: [Implementing a Trait](https://doc.rust-lang.org/book/ch10-02-traits.html#implementing-a-trait-on-a-type).

### Derived traits

```rust,ignore
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
pub struct ClinicId(u64);
```

`derive` writes common trait implementations for you:

- `Debug`: printing with `{:?}`, which `assert_eq!` needs.
- `Clone`, `Copy`: an ID is copied instead of moved, so it can still be used
  after being passed by value.
- `PartialEq`, `Eq`: comparison with `==`.
- `Hash`: use as a key in a `HashSet` or `HashMap`.

`Email` derives `Clone` but not `Copy`, because it owns a `String`, and a
`String` can't be copied bit for bit.

Book: [Derivable Traits](https://doc.rust-lang.org/book/appendix-03-derivable-traits.html).

### `let ... else`

```rust,ignore
let Some((local, domain)) = address.split_once('@') else {
    return false;
};
```

If the pattern matches, the bindings are available after the statement.
If not, the `else` block runs and must leave the function.

Book: [let...else](https://doc.rust-lang.org/book/ch06-03-if-let.html).

### Integration tests

Files in `crates/domain/tests/` are integration tests. Each one is compiled
as a separate crate that uses `clinic_domain` like any other user would, so
it can only reach public items. That keeps the tests on the public API.

Book: [Test Organization](https://doc.rust-lang.org/book/ch11-03-test-organization.html).

## Design choices worth questioning

- **IDs wrap a `u64`, and any value is accepted.** Postgres will probably
  generate them later. UUIDs would be the alternative if IDs had to be
  created outside the database.
- **The whole address is lowercased.** The standard allows the part before
  `@` to be case-sensitive, but almost no mail server treats it that way,
  and lowercasing means `Ana@x.com` and `ana@x.com` are the same user.
- **The length limit counts bytes.** `str::len` returns bytes, not
  characters. 254 is the practical limit for an address.
- **A shape check, not full RFC 5322.** The only real proof that an address
  works is sending mail to it.

## Tests

- IDs: the value round-trips, equal values are equal, an ID is still usable
  after being passed by value (`Copy`), and IDs work in a `HashSet`.
- Email: normalization, case-insensitive equality, `Display`, the exact
  length boundary (254 accepted, 255 rejected), a table of malformed
  addresses, and that the error has a message and implements `Error`.
