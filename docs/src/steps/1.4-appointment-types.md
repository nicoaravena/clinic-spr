# 1.4 Appointment types and status

## Goal

Let each clinic define its kinds of appointment with a fixed duration, and
model the lifecycle of an appointment as a set of allowed moves.

Roadmap row: *Clinic-defined `AppointmentType` with a duration,
`AppointmentStatus`*. Concepts: enums, `match`, `Option`.

## What changed

## Rust concepts

### Enums as a closed set of states

```rust,ignore
pub enum AppointmentStatus {
    Scheduled,
    Completed,
    Cancelled,
    NoShow,
}
```

A value is exactly one of these. Unlike a status string, a typo can't
produce a fifth state.

Book: [Defining an Enum](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html).

### `match` on tuples and exhaustiveness

```rust,ignore
pub fn transition_to(self, next: Self) -> Option<Self> {
    match (self, next) {
        (Self::Scheduled, Self::Completed | Self::Cancelled | Self::NoShow) => Some(next),
        (Self::Scheduled, Self::Scheduled)
        | (Self::Completed | Self::Cancelled | Self::NoShow, _) => None,
    }
}
```

Matching on the pair `(from, to)` turns the transition table into code.
`|` combines patterns. The compiler checks that every combination is
covered. The current status is always named, never `_`, so adding a new
status won't compile until someone decides its moves.

Book: [The match Control Flow Construct](https://doc.rust-lang.org/book/ch06-02-match.html).

### `Option` and the `?` operator on it

```rust,ignore
pub fn slot_starting_at(&self, start: DateTime<Utc>) -> Option<TimeSlot> {
    let end = start.checked_add_signed(self.duration)?;

    TimeSlot::new(start, end).ok()
}
```

`Option` means "a value or nothing". `?` on an `Option` returns `None` from
the function early. `.ok()` turns a `Result` into an `Option` and drops the
error.

Book: [The Option Enum](https://doc.rust-lang.org/book/ch06-01-defining-an-enum.html#the-option-enum-and-its-advantages-over-null-values)
and [the ? operator](https://doc.rust-lang.org/book/ch09-02-recoverable-errors-with-result.html#a-shortcut-for-propagating-errors-the--operator).

### Taking `&str`, storing `String`

`AppointmentType::new(name: &str, ...)` borrows the input, trims it, and
stores an owned copy with `to_owned()`. Callers can pass a literal or a
`String` without giving it up. `name()` returns `&str`, a view into the
stored string, so nothing is copied.

Book: [String Slices](https://doc.rust-lang.org/book/ch04-03-slices.html#string-slices).

### Checked arithmetic

`checked_add_signed` returns `None` instead of panicking when the result
would fall outside the dates chrono can represent.

## Design choices worth questioning

- **Appointment types are data, not an enum.** Every clinic defines its own,
  so they can't be known at compile time. Statuses are the same for
  everyone, so they are an enum.
- **`transition_to` returns `Option`, not `Result`.** There is only one way
  to fail ("not allowed"), so `None` says enough. Step 1.6 may need a
  richer error when this becomes part of booking.
- **`.ok()` drops the `TimeSlot` error.** The duration is always positive,
  so `TimeSlot::new` can't fail here. Only the overflow case returns `None`.
- **`TimeDelta` for the duration,** not a number of minutes, so the unit
  can't be misread.
- **A status isn't attached to an appointment yet.** There is no
  `Appointment` entity so far. It arrives with booking.

## Tests

The name and duration round-trip, the name is trimmed, empty and
whitespace-only names are rejected, zero and negative durations are
rejected, the slot lasts exactly the duration, out-of-range dates give
`None`, and the error has a message and implements `Error`. For statuses:
`Scheduled` reaches every final status, `Scheduled -> Scheduled` is refused,
and a final status can't move anywhere.
