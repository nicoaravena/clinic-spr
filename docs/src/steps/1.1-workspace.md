## Rust concepts

### Cargo workspaces

A workspace is a set of crates that share one `Cargo.lock` and one
`target/` directory. The root manifest lists its members:

```toml
[workspace]
resolver = "3"
members = ["crates/*"]
```

The glob means any new directory under `crates/` joins the workspace. The
`api`, `app` and `db` crates will be added there in later milestones.
`resolver = "3"` is the dependency resolver that goes with edition 2024.

Book: [Cargo Workspaces](https://doc.rust-lang.org/book/ch14-03-cargo-workspaces.html).

### Crates and their names

The package is called `clinic-domain` in `crates/domain/Cargo.toml`. Rust
identifiers can't contain `-`, so code imports it as `clinic_domain`, for
example `use clinic_domain::ids::ClinicId;`.

Book: [Packages and Crates](https://doc.rust-lang.org/book/ch07-01-packages-and-crates.html).

### Modules

`src/lib.rs` is the crate root. Each `pub mod name;` line tells the compiler
to load `src/name.rs` as a module and make it visible outside the crate:

```rust,ignore
pub mod schedule;
```

Book: [Defining Modules](https://doc.rust-lang.org/book/ch07-02-defining-modules-to-control-scope-and-privacy.html).

### Unit tests

A function marked `#[test]` is run by `cargo test`. Unit tests sit inside
the module they test, in a `tests` module that is compiled only for tests:

```rust,ignore
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn end_minute_adds_duration_to_start() {
        let result = end_minute(540, 30);
        assert_eq!(result, 570);
    }
}
```

`use super::*` brings the parent module's items into scope, private ones
included.

Book: [How to Write Tests](https://doc.rust-lang.org/book/ch11-01-writing-tests.html).

## Design choices worth questioning

- **A workspace from day one, with one crate.** It costs one extra manifest.
  In return, the roadmap's rule that the domain has no I/O is enforced by
  crate boundaries: `clinic-domain` can't use `sqlx` or `axum` unless they
  are added to its own `Cargo.toml`.
- **`end_minute` is a placeholder.** It only exists to have something to
  test. Step 1.6 replaces `schedule.rs` with real booking rules.

## Tests

One unit test checks that `end_minute(540, 30)` is `570`. Later steps put
their tests in `crates/domain/tests/` instead (see 1.2).
